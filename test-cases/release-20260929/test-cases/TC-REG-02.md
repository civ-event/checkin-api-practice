# TC-REG-02: 充值订单唯一键是角色加订单号

| 属性 | 值 |
|------|-----|
| 编号 | TC-REG-02 |
| 优先级 | P2 |
| 模块 | 回归 |
| 平台 | Server |
| 关联需求 | 迁移 `009` 把唯一键改成 `(role_id, order_id)` |
| 关联 CR | 7.4「旧库若只跑过 008、没跑 009」；CR-6 的前提 |

## 前置条件

- 应用库已执行 `scripts/pdo_migrate.php`。`schema_migrations` 里能看到 `009` 对应的文件名。
- 不要手工重跑 `009` 的删除语句。

## 操作步骤

1. 查 `schema_migrations`，确认 `009` 已记录。
2. 查 `recharge_payment_orders` 的唯一索引定义。
3. 选一个已存在的 `role_id + order_id`，尝试再插入一行，金额改成另一个正数。

## 预期结果

- 第 1 步有 `009` 的迁移记录。
- 第 2 步唯一键是 `(role_id, order_id)`，不是 `(role_id, order_id, amount, send_time)`。
- 第 3 步插入失败，重复键错误。表中该订单仍只有原来那一行，金额不变。

## 不应出现

- 同订单号、不同金额各占一行，再被合计加两次。
- 为了验证去把 `009` 再执行一遍。该脚本会删重复行。

## 备注

- 应用层合计仍有 `ORDER BY id` 和 PHP `$seen`。在本条唯一键成立时，去掉它们不应改变 `totalRechargeGoods`（CR-6）。本条不改代码，只确认唯一键已经是这个前提。
