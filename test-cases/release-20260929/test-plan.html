测试陷阱

  • 不要用宿主机日期判断签到第几天。容器从 2026-10-10 17:00 UTC 起算，之后继续走。PHP 显示的是 Asia/Shanghai。
  • 不要断言 date() 永远等于 2026-10-10。FAKETIME 带 @。
  • 不要预期成功体为 {code,message,data}。成功是控制器数组原样 JSON。错误才有 code 和 exception。
  • 不要断言角色乙合计一定是 600。种子 send_time 在上海和 Etc/GMT+5 都落在 2026-09。10 月合计不含这 600。乙的服务器是 Asia/Shanghai，与 game.php 一致。
  • 前端路径 monthly-cumulative-recharge 没有 record。入账打 /api-front/activity/recharge/record。
  • routes.yml 的 record 注释与代码一致：amount 写入订单表，再按当月合计。按 TC-PAY-02 断言增加 100。
  • 旧库若只跑过 008、没跑 009，同订单号不同金额仍可能各插一行。
  • 探活 /、/memcached、/lock、/db 是纯文本。/json 才是 {"ok":true}。
  • 对外端口以 HTTP_PORT 为准。
  • 连续写接口间隔太短会 409 RESOURCE_BUSY。锁墓碑约 1 秒，不要当成业务错误码。
  • 重启 app 后假时钟跳回锚点。若 last_check_time 落在未来，签到 status 为 500，日志是 lastCheckTime is in the future。
