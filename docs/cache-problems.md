# 签到 status 缓存：穿透 / 击穿 / 雪崩

结合本项目 `CheckInStatusCache` 的做法：

## 缓存穿透（Penetrate）

**现象**：大量请求查询根本不存在的 key（或非法参数），每次都打到 DB。

**本项目手段**：

- Controller 先校验 `X-Role-Id` / `X-Activity-Id` 必须为数字，非法请求直接 10004，不查库、不写缓存。
- 合法但尚无进度的用户会 `findOrCreate` 后缓存真实空进度，而不是反复用“不存在”打穿。

## 缓存击穿（Breakdown / Hot key）

**现象**：某个热点 key 在过期瞬间，大量并发同时回源 DB。

**本项目手段**：

- `remember()` 在 miss 后用 `key:build` 短锁，只让一个请求重建缓存。
- 其他请求短暂等待后再读缓存；仍没有则各自回源（学习实现，可接受）。

## 缓存雪崩（Avalanche）

**现象**：大量 key 在同一时刻集体过期，DB 被打满。

**本项目手段**：

- TTL = 45s + `[0,15]` 随机抖动，避免齐步过期。

## 一致性

签到成功后 `forget()` 删除 status 缓存，避免长时间脏读。
